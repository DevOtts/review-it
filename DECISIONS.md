# DECISIONS

## 2026-10-18 review-it to status-write wiring

- D-01 [tests] Default: add `node --test` + `node --check`. `git ls-files` shows no versioned runner or package.json. Recommendation: keep it; run `node --test plugins/review-it/tests/status-sync.test.mjs` (or the glob `node --test 'plugins/review-it/tests/*.test.mjs'`). The bare directory form `node --test plugins/review-it/tests` fails on Node 22 (it is resolved as a module, not a test dir). Tests skip (not fail) when status-write.mjs is not found; set STATUS_WRITE to point at it.
- D-02 [evidence] Default: the sync script cuts one `verdict-<TASK>.md` per PASS task beside the report instead of passing the report itself as `--evidence`. Why: the writer refuses a file with any non-PASS `verdict:` line, and a multi-task report has both. Recommendation: keep; the full report is linked from the verdict file (`report:` line).
- D-03 [report format] Default: new additive section 2c "Task results" (`task:` / `verdict:` / `note:` blocks) is how tasks are mapped to cases. Recommendation: build-it/plan-it should name tasks the same way in the contract so cases carry their task id.
- D-04 [writer location] Default: resolved from `--writer`, `STATUS_WRITE`, then `~/Workspace/Devotts/build-it/...`. Recommendation: when build-it ships the writer inside the installed plugin, point the default there.
- D-05 [scope] Correction (2026-10-18, PR #5 fix): the root `SKILL.md` is a regular file, not a symlink, and it does not carry the status-sync section; only `plugins/review-it/skills/review-it/SKILL.md` (the copy the plugin loads) was edited. Syncing the root copy is left open. No version bump, per instructions.
- D-06 [no false verified] (fix for the PR #5 verifier, B1-B3) A task is synced as verified only when the report's overall `verdict:` (header, before the first `task:` block, exactly once) is PASS and the task's own 2c block says PASS. Lines inside ``` / ~~~ fences, 4-space indented code and HTML comments are ignored. Overall FAIL or missing: nothing is verified, FAIL tasks go to in-progress with a note, PASS tasks are left unchanged. Ambiguity (duplicate task block, two verdicts in a block, two overall verdicts, a value other than PASS/FAIL, a verdict line outside any block after the first task, a task not on the board) is exit 1 with nothing written. Each verdict file records `report:` and `report_sha256:`. The main() guard compares real paths, so a symlinked install, `/tmp` and paths with spaces run.
